Design system

One reference for how OpenGym looks: the new color palette, a type scale, every icon in use, and the shared patterns for headers, lists and tables, buttons, controls and popups. Each pattern lists its sizes in px (and the Tailwind classes that make them), so a mockup or a new screen can be built from this page without guessing.

It was written from the app as it is today (src/index.css, src/components/ui.tsx, overlays.tsx, icons.tsx, the screens and the storyboard). Where the code is already consistent, this page just writes it down. Where it isn't (28 font sizes, 15 corner radii, three kinds of dashed "+ Add" button), it picks one value and the cleanup list in §13 says what moves. §11 covers the nutrition prototype's new patterns, and §12 turns nine of the busier screens into recipes.

Five rules that cover most decisions

  • Flat and black. Black canvas, flat rows, 1 px hairlines. No cards, shadows or gradients. Grey fills (surface) only mark something you can tap or type into.
  • Color means something and is never alone. Blue = act / selected, green = better, orange = attention, red = delete / worse. Always next to a word or a symbol.
  • Numbers are the loudest thing. Logged weights and reps are bold, white and tabular. Labels around them are small and grey.
  • One size per job. Pick from the scales on this page (type, spacing, heights, radii). A new value needs a reason written next to it.
  • 44 px to touch. Anything tappable has a 44 × 44 target, even when what you see is smaller (a 32 px button sits in a 44 px hit area).

How to use it

  • Two blues. Bright #007AFF for text, glyphs, outlines, focus rings and chart marks. Deep #0066D6 for anything filled. White text never sits on the bright blue (4.0 : 1).
  • Text is white or grey. White for what you logged and named; fg2 for anything you need to read but isn't the point (dates, units, meta). fg3 only for things that carry no information.
  • Status colors are for status. Green, orange and red never decorate. Each one comes with a word or a drawn symbol: the up arrow before +9%, "Missed", ✕ Delete.
  • Macros are blue, cyan, gold. Protein uses the primary blue itself, not a look-alike. They never change with state. Fat stays gold when over target; the "over" note is orange text next to it. Protein above its floor gets a ✓, not a color change.
  • Colored fills with text on them (orange D badge, green or gold chips) use black text. Blue and red fills use white text on the deep variants.
  • No literals. Every color is a --og-* variable. Today #2e8bff is typed in six files; see §13.

Weights

  • 700 bold: titles, names, logged numbers, filled button labels, caps labels, badges.
  • 600 semibold: labels inside controls (segmented, chips, dashed add, bordered buttons), input values, label actions.
  • 500 medium: only Back / plain bar buttons and keypad digits.
  • 400 regular: copy, subtitles, sheet and menu options.
  • 800: only the one-letter W / D badges.

Numbers and text

  • A set is 185 × 8 (thin spaces around ×), BW × 12, +25 × 8, −40 × 10. Real minus sign (−), not a hyphen.
  • Units go in the column header (LBS) or after the number in grey: 207 lb.
  • Dates: Thu, Oct 29; inside a week, the weekday ("Mon").
  • Empty value: an em dash — in fg2, never 0.
  • Sentence case everywhere except caps labels and badges. No trailing periods on labels or buttons.
  • Truncate names with an ellipsis on one line; never wrap a row title to three lines.

Column rules

  • Text left, numbers right. In read-only tables numbers are right-aligned so digits stack. In editable tables (set and cardio tables) numbers are centered in their cell.
  • Fixed px for number columns, sized for the longest value ("1,000", "12:45"); one minmax(0,1fr) column takes the rest and truncates.
  • Units in the header ("LBS", "KM"), never repeated in cells.
  • Bold the value, not the label. The thing you're comparing is 700; everything else is 400 or fg2.
  • Empty is — in fg2. A row that can't be computed explains why in the footnote.
  • Status in tables uses the color plus a TrendUp / TrendDown glyph or a word, never color alone.

Principles: the checklist for a new screen or mockup

From SPEC §8, kept short. A mockup that passes these and uses only values from this page will look like the rest of the app.

Do
  • Logging is the product. One tap completes a set; values come pre-filled; typing is the exception.
  • Thumbs low, decisions high. The set tick, + Set, Prev / Next, keypad and Start at the bottom; Save / Done top right, Cancel / Back top left.
  • Start from a pattern. Large title or top bar → section labels → rows or a table → one bottom action.
  • Pair every color with a word or symbol, and every gesture with a visible control.
  • Forgive. Undo toast after deletes; alert only before losing logged work.
  • Use the components. If ui.tsx or overlays.tsx has it, use it rather than restyling inline.
Don't
  • Cards, shadows (only the effort badge keeps its small one), gradients or colored backgrounds for sections.
  • A second filled button on the same screen, or a filled button in a top bar (Finish is the exception).
  • New sizes, radii or colors that aren't on this page. Half-pixel font sizes.
  • Status colors as decoration, or macro colors that change with state.
  • Grey text for numbers you logged; white text for meta.
  • Alerts for information, toasts for errors, or a hold menu as the only way in.
